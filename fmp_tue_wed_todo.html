FSB_PaR — Tuesday & Wednesday

A two-day task list for the Phase 1 Data Integrity Audit. Tiny steps. Big boxes. Less chance of the task list biting back.
Main rule: Do one box at a time. Stop when FileMaker asks you to decide something.

Tuesday

Check the small things first

1

Start Claude the safe way

Use /fmp-session-control. Ask for one chunk only.

Say: “Current target: Phase 1 Data Integrity Audit / Fix Pass.”
2

Check TimeEntries Save → Review

Open TimeEntries. Save a test record. Click Review in the save message.

Pass = it lands on LYT_TimeEntries_Review.
3

Check TimeEntries Export Cancel

Open TimeEntries Review. Click Export List to Excel. Click Cancel first.

Pass = no file is made and no records change.
4

Check ReportingCodes Save → Review

Open Reporting Codes. Save a test code. Click Review in the save message.

Pass = it lands on LYT_ReportingCodes_Review.
5

Check TimeEntries sidebar fields

Check each sidebar audit field one at a time.

Browse Mode = OFF. Find Mode = ON.

Wednesday

Start the real audit list

1

Make the audit table

Write down each layout name. Leave space for notes: Can edit? Save checks? Fix needed?

Layouts: PayRates, Assignments, Pursuits, Bonuses, TimeEntries, ReportingCodes.
2

Test saved-record editing

Open an old saved record. Try changing a safe field. Do not keep the change.

Write: “Can edit old record: Yes / No.”
3

Check Save required fields

Try saving with required fields empty. Check if the warning stops the save.

Write: “Save validation: Works / Broken / Not sure.”
4

Look at Status and Notes

Decide if old records should allow Status or Notes changes.

Do not fix yet. Just write the decision question.
5

Pick the first fix target

Choose the worst layout from the audit list. Usually the one that lets old important records change too easily.

Stop before changing scripts. Get the fix pattern approved first.

Use this simple audit checklist

  • Can I edit an old saved record?
  • Does Save stop me when required fields are empty?
  • Should old records become read-only?
  • Do we need Correction, Void, or Supersede buttons?
  • Should Status and Notes stay editable?
  • Does Cancel behave safely?
  • Do code pickers need filtering by type or active status?

Do NOT do these yet

  • Do not start Vendors.
  • Do not start Receipts.
  • Do not add Sage or QuickBooks fields.
  • Do not delete raw layouts until routing is proven safe.
  • Do not invent a locking fix layout by layout.

Tiny mercy: this is a checking pass first. Fixes come after the pattern is chosen.

Print in landscape if possible. Mark boxes with a pen. Primitive, effective, and somehow still better than most project-management software.
