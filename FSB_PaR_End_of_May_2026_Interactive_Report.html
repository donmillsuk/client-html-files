4. Main risks before testing handover

The awkward bits that must not be brushed under the office carpet.

  • Saved records must be protected from casual editing. Users should not be able to overwrite historical, payroll, time-entry, bonus, or setup data without control.
  • Correction, void, and supersede workflows need finishing. Legitimate changes should be tracked rather than typed over old values.
  • Real ReportingCode records are still needed. Sandy/Cindy must supply or confirm the actual CostCode and PayrollCode lists.
  • The first saved-record protection pattern is still being designed. EmployeePayRates is the first target, and complexity there may affect the rest of the audit.
  • Wording, spelling, help popovers, and export instructions still need polish. Humans read labels, sadly, so labels must behave.
  • User/bookkeeper training material is still needed. Especially for searching, exporting, Save As behaviour, ReportingCodes setup, and correction workflow.

5. Next work planned

The practical route from built screens to testing handover.

  1. Complete the Phase 1 Data Integrity Audit / Fix Pass.
  2. Implement saved-record protection where approved.
  3. Add or confirm controlled workflows such as Supersede, Void, Close, Reopen, Retire, Mark Posted, or similar where needed.
  4. Prepare and import real ReportingCodes once the source lists are confirmed.
  5. Complete cleanup and handover-readiness checks.
  6. Prepare simple user/bookkeeper training material.
  7. Start controlled testing handover.
